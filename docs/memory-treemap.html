Top level

Watchdog

The bootloader leaves the watchdog running when it starts the firmware, with a 5 second timeout. It keeps counting while the chip sleeps and pauses while a debugger has it halted. The firmware must take it over with exactly those settings.

The firmware feeds it only while the button is up. Holding the button for about 5 seconds resets the watch into the bootloader, and 5 seconds more installs the recovery firmware. An update that never confirms itself is rolled back.

Flash layouts: boot/src/lib.rs (crate battletime-boot). Details: Memory map, Bootloader and Storage; source in BeatLink/BattleTime, this page at docs/memory-treemap.html.
The firmware builds, static RAM, stack and file system are measured by tools/measure_memory.py, which CI reruns on every push to master and writes into this page. The rest comes from the docs and is updated by hand: the bootloader and shared library sizes, the deepest stack path, and the split of the firmware's static RAM into tables, buffers and tasks.
